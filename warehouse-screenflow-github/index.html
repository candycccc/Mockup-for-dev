4 suggestions · Proposed
01

Menu / Select Location

Select the working warehouse before Menu

Design the mobile experience around warehouse operatives handling goods at their working warehouse. Select or confirm that warehouse before entering Menu, and keep Goods In, Goods Out, Search Stock and Activity scoped to it. Display the selected warehouse consistently. Routine item searches should not require browsing other warehouses.

Select warehouse → Menu → Operations in the selected warehouse

Proposed screens are illustrative wireframes; work-list orders and counts are example data. The bottom navigation contains Menu, Search Stock, Activity, Overview and Cart.

02

Main navigation / Stocked Items

Add Search Stock to the bottom navigation

Add Search Stock to the bottom navigation alongside Menu, Activity, Overview and Cart. Open the selected warehouse’s stock list directly, with search and scanning available immediately. Staff should be able to look up an item from any main screen without returning to Menu or selecting the warehouse again.

Bottom navigation → Search Stock → Items in the selected warehouse

Proposed screens are illustrative wireframes; work-list orders and counts are example data. The bottom navigation contains Menu, Search Stock, Activity, Overview and Cart.

03

Product Detail / Item Actions

Show all seven actions on Product Detail

Keep all seven actions visible: Print Labels sits in the top-right header beside the profile icon, and the six stock actions form a two-column grid below the stock summary. Move Item remains the proposed primary action for warehouse operations. Keep the warehouse, all six stock figures, stock tabs, bin-level Move buttons and related records on the same page.

Product Detail → visible action button → action form → review or confirmation
LAYOUT PREVIEW · NEXT STEP

Try an action button above

This preview describes the next screen. It does not submit a stock change, edit a cart or start printing.

Button placement & behaviour

  1. Place Print Labels in the top-right header, before the profile icon. Use a printer icon with a short visible label, an accessible name and a tooltip; remove the duplicate from the action grid.
  2. Prioritise Move Item for relocating goods between bins. Keep Adjust Qty secondary for correcting a verified difference between physical and recorded stock. This recommendation follows the warehouse-operative context, not measured usage frequency.
  3. Arrange the six stock actions in three rows of two, with full text labels and buttons at least 48 px tall. Allow Assign to Another Job to wrap rather than truncate it.
  4. Keep each bin’s Move shortcut. It opens the same move flow with that source bin already selected.
  5. Let the page scroll naturally. Keep the six stock actions together above the stock tabs. Printing remains directly available in the header; no three-dot menu is required.
  6. Keep role and stock-eligibility rules. An unavailable action needs a visible reason; tapping a button starts its flow rather than immediately changing stock.

Proposed screens are illustrative wireframes; work-list orders and counts are example data. The bottom navigation contains Menu, Search Stock, Activity, Overview and Cart.

04

Menu / Goods In & Goods Out

Compare status menus and direct order listing

Compare two versions of the same warehouse Menu. Option A starts with status rows and counts. Option B starts with the order list and provides a status filter. Both use Goods In / Goods Out tabs, AV Warehouse and the same example orders. Neither version is marked as approved.

A: Tab → Status → Order list → Order detail | B: Tab → Order list → Order detail

Shared rules & option behaviour

  1. Both options keep the selected warehouse, Goods In / Goods Out tabs and the five bottom destinations: Menu, Search Stock, Activity, Overview and Cart.
  2. Place the Goods In / Goods Out tabs directly below the working warehouse. Omit the Warehouse Menu heading and subtitle so more operational content fits on screen.
  3. Option A shows Incoming, Arrived, Receiving and Put away, or Confirmed, Picking and Ready to Dispatch. Each row displays its count; selecting it opens the matching order list. The total stays in the Goods In / Goods Out tab, with no separate All Goods In / All Goods Out row.
  4. Option A keeps zero-count stages visible. Back to status menu returns to the rows. Searching directly from the status menu is also available.
  5. Option B opens all orders immediately. Search and the status filter narrow the list, and each order keeps its status visible. Clearing the search returns to the order list.
  6. The comparison uses the same orders and counts on both sides. Changing direction switches both previews and restores their starting views, so the comparison stays consistent.
  7. Open an order before recording quantities or confirming a stock operation. Reducing navigation must not bypass receipt, picking or dispatch checks.
  8. Decision pending: review whether operators usually choose work by stage or look for a specific order. Earlier warehouse-selection and Search Stock illustrations show Option A only; that is not an approval decision.
